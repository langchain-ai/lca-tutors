# Getting Set Up (Python)

Follow these steps to get your environment ready for the course.

---

## Setup

### Prerequisites

- Python 3.11–3.14
- [uv](https://docs.astral.sh/uv/): [how to install](#installing-uv)
- Model access: use a direct provider key (Anthropic by default, [create a key here](https://console.anthropic.com/)), or use [LangSmith LLM Gateway](https://docs.langchain.com/langsmith/llm-gateway-direct-model-access#configure-langchain-and-deep-agents) for supported chat models
- LangSmith API key: [how to get one](#getting-started-with-langsmith)
- Tavily API key (optional, for the Module 4 & 5 web-search labs): [get a free key](https://app.tavily.com)
- Windows: supported through [WSL (Windows Subsystem for Linux)](https://learn.microsoft.com/en-us/windows/wsl/install)

### Installation

Clone the repository and move to the `python` directory:

```bash
git clone --depth 1 https://github.com/langchain-ai/lca-deepagents.git
cd lca-deepagents/python
```

Make a copy of `.env.example`:

```bash
cp .env.example .env
```

Insert API keys directly into `.env`. The example below uses direct provider access; Gateway users can use the alternative immediately below it:

```bash
# LangSmith: tracing and observability
LANGSMITH_API_KEY=lsv2_...
LANGSMITH_TRACING=true
LANGSMITH_PROJECT=lca-deepagents
# Non-US region? Uncomment your endpoint (else your API key won't authenticate):
# LANGSMITH_ENDPOINT=https://eu.api.smith.langchain.com    # GCP EU
# LANGSMITH_ENDPOINT=https://apac.api.smith.langchain.com  # GCP APAC

# Model provider API keys: set the one you're using
ANTHROPIC_API_KEY=your-anthropic-api-key
# OPENAI_API_KEY=your-openai-api-key
# GOOGLE_API_KEY=your-google-api-key

# OpenRouter: optional, for trying free hosted open-source models (used in the Models lesson)
# Get a free key at https://openrouter.ai/keys
# OPENROUTER_API_KEY=sk-or-v1-...

# Tavily web search - for the research labs (Module 4 and the Module 5
# newsletter). Leave blank to run those labs without web search.
# Get a free key at https://app.tavily.com
TAVILY_API_KEY=
```

**Gateway alternative:** for supported LangChain chat models, set the following in `.env` and remove the unused provider-key placeholders:

```dotenv
LANGSMITH_GATEWAY=true
LANGSMITH_API_KEY=your-workspace-scoped-langsmith-key
```

The key needs `gateway:invoke`. To use a separate key for model requests, set `LANGSMITH_GATEWAY_API_KEY`; tracing still uses `LANGSMITH_API_KEY`. Gateway routing and `LANGSMITH_TRACING` are independent. For a non-US Gateway, use its full regional Gateway URL as `LANGSMITH_GATEWAY`, rather than the tracing API endpoint. Leave Gateway unset or set it to `false` to use provider keys directly.

Gateway support requires `langchain-anthropic>=1.5.1` for Anthropic or `langchain-openai>=1.4.1` for OpenAI. Check the [Gateway documentation](https://docs.langchain.com/langsmith/llm-gateway-direct-model-access#configure-langchain-and-deep-agents) for other integrations. Install the course dependencies below, and verify the installed integration version before relying on Gateway routing.

This configuration applies to supported chat models, not automatically to raw SDK clients, embeddings, remote deployments, or the coding agent hosting this tutor. Keep the credentials those paths require. Tavily web search also needs its own key when used.

This course uses `load_dotenv(override=True)`; `.env` values always win over OS environment variables.

Install dependencies:

```bash
uv sync
```

### Setup Verification

After completing the steps above, run the following to verify your environment:

```bash
cd python
uv run python env_utils.py
```

You should see masked values for credentials and a report for the selected authentication path. A missing provider key is expected for supported Gateway chat calls; a missing Gateway credential is not. Check the reported issues rather than treating every `<not set>` entry as an error.

## Setup Details

### Setup Verification Issues

<details>
<summary>ImportError when running env_utils.py</summary>

If you see `ModuleNotFoundError: No module named 'dotenv'`, you're likely running Python outside the virtual environment.

**Solution:** Use `uv run python env_utils.py` (recommended), or activate the virtual environment first:
- macOS/Linux: `source .venv/bin/activate`
- Windows: `.venv\Scripts\activate`

</details>

<details>
<summary>A key shows &lt;not set&gt;</summary>

The variable is absent from your active environment. It may belong to an unused provider or an optional lab.

**Solution:** For direct chat access, fill in the key for your chosen provider. For Gateway chat access, verify the Gateway flag and credential instead; leave unused provider keys unset. Fill in separate tool or other credentials only for the lessons that use them.

</details>

<details>
<summary>LangSmith tracing errors</summary>

If you see tracing errors at runtime, check that both `LANGSMITH_TRACING=true` and a valid `LANGSMITH_API_KEY` are set in your `.env` file. If you don't have a LangSmith account yet, set `LANGSMITH_TRACING=false` to disable tracing until you do.

</details>

<details>
<summary>Wrong Python version</summary>

The course requires Python 3.11–3.14.

**Solution:** If using `uv`, run `uv sync`; it will install the correct Python version automatically. If using pip, install Python 3.11–3.14 from [python.org](https://www.python.org/downloads/).

</details>

### Installing uv

See the [uv installation docs](https://docs.astral.sh/uv/getting-started/installation/) for full instructions. Common options:

```bash
# macOS / Linux

# macOS with Homebrew
brew install uv

# Windows
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```
